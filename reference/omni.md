# Gemini Omni 1.1 Flash — Video Generation (default Google video model since 2026-09)

Model id `gemini-omni-1.1-flash` (stable; `gemini-omni-flash-preview` is the older preview). Replaces Veo 3.1 in this
studio (`scripts/generate_video_veo.py` kept as a fallback). Docs: https://ai.google.dev/gemini-api/docs/omni

Script: `scripts/generate_video_omni.py` — talks to the **Interactions REST API** directly
(`POST https://generativelanguage.googleapis.com/v1beta/interactions`, header `x-goog-api-key`) because the
Interactions API only exists in `google-genai >= 2.x` which needs Python 3.10+. Works on the system Python 3.9.

## What it can do

| Capability | Flag | Notes |
|---|---|---|
| Text-to-video | `--prompt` | 3–10 s per generation, 24 fps, native audio |
| Image-to-video (first frame) | `--image still.png` | the still carries the look; prompt = motion/camera/light/audio only |
| First + last frame | `--image a.png --last-frame b.png` | interpolation between two stills |
| Subject / style references | `--ref char.png --ref prop.png` | address as `<IMAGE_REF_0>`, `<IMAGE_REF_1>` in the prompt |
| Reference video clips | `--ref-video x.mp4` | max 3 clips, ≤3 s each (camera / motion / style) |
| Extend a clip | `--extend clip.mp4 --prompt "Continue: ..."` | input ≤10 s, appends 3–10 s, chain to 40 s total; end only |
| Edit a clip | `--edit clip.mp4 --prompt "Make the sky overcast. Keep everything else the same."` | input ≤10 s |
| Multi-turn refine | `--previous <interaction_id>` | id printed after every run and saved in `<output>.json` |
| Draft → upscale | `--resolution 360p` then `--upscale draft.mp4 --resolution 4k` | 360p is ~⅓ the cost and 60 % faster; 1080p/4K are upscales of 720p |
| Aspect | `--ratio 16:9 \| 9:16` | only these two |
| Resolution | `--resolution 360p \| 720p \| 1080p \| 4k` | 720p default |
| Duration | `--duration 3..10` | no API field — the script writes "A N-second continuous shot." into the prompt |
| Recover a finished output | `--download files/<id>` or `--download <interaction_id>` | no regeneration cost |

Cost (Sept 2026, per second of output): 360p $0.03 · 720p $0.10 · 1080p $0.15 · 4K $0.30. A 6 s 720p clip ≈ $0.60.
Every output carries an invisible SynthID watermark. Editing/extending *uploaded* videos is unavailable in EEA/CH/UK.

## Prompting Omni

- One continuous shot per generation: say so — *"In a single continuous shot, no scene cuts."*
- Timing in natural language: *"After 3 seconds a hand enters from the left."* / *"The chorus starts at 5 seconds."*
- Camera: name the rig — *continuous handheld*, *slow dolly in*, *locked-off*, *drone*. One move per clip.
- Audio is generated by default. Ask for what you want (*"soft rain, no music, no dialogue"*) or it will invent music.
- Style/subject refs: *"in the style of <IMAGE_REF_0>"*, *"the character in <IMAGE_REF_1>"*.
- Edits: short prompt + *"Keep everything else the same."*
- Image-to-video with a strong still: 30–80 words of pure change (light breathing, wind, a hand entering). The
  LTX lessons apply — never mention particles/dust/fluids unless wanted (see `learnings.md`).
- English only is evaluated. No system instructions, temperature or top_p.

## Where Omni sits vs. the other video models

| | Omni 1.1 Flash | Seedance 2.5 | LTX 2.5 / 2.3 |
|---|---|---|---|
| Faces | ✅ | ❌ (Seedream workaround) | ✅ |
| Per-gen length | 3–10 s (+extend to 40 s) | 4–30 s | 6–20 s / 2–20 s |
| Reference videos | 3 × ≤3 s | 10 × ≤30 s total | — |
| Edit existing footage | ✅ conversational | ✅ edit/extend | retake (2.3 pro) |
| Cheap drafts | 360p at $0.03/s | `--model mini` | `ltx-2-3-fast` |
| Best for | hero shots with people, conversational fixes, draft→4K | 30 s one-take ads, product/3D, "camera like @Video1" | budget coverage, long takes, retakes |

## Verified 2026-09-04

- GPT Image 2 still → Omni image-to-video 360p 16:9, 4 s: `task=image_to_video`, delivery `uri`, ~50 s wall time.
- Text-to-video 360p 9:16, 3 s: audio track present, 24 fps, `status: completed` synchronously (no polling needed).
- Gotchas fixed in the script: the output `uri` already ends in `:download?alt=media` (parse `files/<id>` out of it);
  authenticate with the `x-goog-api-key` header, never `?key=` (it leaks into error messages).
